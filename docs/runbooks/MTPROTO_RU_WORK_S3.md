# Work → RU «Избранное» на отдельном staging

S3 поднимает отдельный Work endpoint по `railway.personal-s3.toml`. Он
ставит команды в журнал и читает квитанции. Запуск воркера выполняется
отдельным операторским действием в сервисе с уже подготовленным томом RU.
Веб-процесс не загружает сессию и не подключается к Telegram. Конфигурация
по умолчанию выключена.

## Конфигурация и проверка

| Настройка | Назначение |
| --- | --- |
| `GATE_ENV=staging`, `GATE_PERSONAL_S3_STAGE_ENABLED=true` | Явно разрешают отдельный вход S3. Конфигурации действующих S1 и S2 остаются отдельными. |
| `GATE_PERSONAL_S3_STAGE_DATABASE_URL`, `…_WORKSPACE`, `…_OWNER`, `…_BINDING_ID`, `…_EXPECTED_PROVIDER_OWNER` | Привязка Work и воркера к одной подготовленной RU-установке. Требуется приватная база S2 на ревизии `0126_personal_standalone_fence` и активная запись собственного аккаунта с совпадающим Telegram ID. |
| `GATE_PERSONAL_S3_STAGE_RESOURCE`, `…_ISSUER`, `…_JWKS_URL`, `…_CLIENT_ID` | Отдельный адрес MCP и проверяемый OAuth-клиент. Подписанные owner, client, workspace и RU account должны соответствовать установке. |
| `GATE_PERSONAL_S3_STAGE_MASTER_KEY` | Отдельный секрет, одинаковый у S3 MCP и оператора воркера. Из него выводятся ключи журнала, гранта и ссылок на адресата. |
| `GATE_PERSONAL_S3_STAGE_GRANT_ID`, `…_GRANT_EXPIRES_AT`, `…_APPROVAL_REF` | Привязка к точному допуску на собственное «Избранное». Грант создаёт только оператор, веб-запуск не создаёт его. |

`python -m app.personal_telegram.s3_stage validate` проверяет параметры
без сети. `preflight` дополнительно читает ревизию БД и точную привязку.
Он не применяет миграции и не открывает том или Telegram. Для живой
приёмки сначала требуется допуск на точный стенд, ревизию и миграцию.

После согласованного оператором `provision` Work получает короткоживущую
ссылку на собственный RU, затем `prepare` и `execute` сохраняют выбранную
команду. Оператор видит зафиксированный текст с одним operation ref.
Только после согласования точного текста и окна он запускает
`run-one --operation-ref <ref> --text-sha256 <sha256> --expires-at <UTC>`
через тот же модуль. Этому запуску также требуются
`GATE_PERSONAL_RUNTIME_ENABLED=true`, прежние параметры RU-воркера
и подготовленный том. Воркер проверяет queued-операцию до чтения тома
и берёт одну операцию по её ID на срок до пяти минут.

Сверьте `result` в Work с одной квитанцией `telegram_<id>`. При
`unknown` требуется сверка исхода, повторный запуск не переотправляет
сообщение. Временно выданные допуски и флаги действуют в пределах
согласованного окна.
