# Защита от устаревшей отправки в Gate #745

1. В начале подготовки Work читает диалог через `gate_get_reply_context` и
   запоминает ID последнего сообщения из поля `context_snapshot`. Для готового
   контекста поле содержит один ID. Work передаёт его в
   `expected_context_snapshot` при подготовке.
2. Gate сохраняет ID в существующей записи черновика. Перед обращением к
   Telegram Gate сверяет только ID последнего сообщения в этом диалоге. В
   проверку входят новые сообщения, которые Gate уже принял, даже если их ещё
   нет в читаемой истории. Для старых записей без Telegram ID используется ID
   записи Gate.
3. При расхождении Gate возвращает в Work `context_changed`, `sent=false` и
   текст «Не отправлено. Пока готовился ответ, диалог изменился». Неотправленная
   часть серии останавливается. Для новой отправки Work читает диалог заново,
   готовит ответ и получает подтверждение.
4. Если ID совпадает, Gate выполняет обычные проверки и отправляет
   подтверждённый ответ. Повтор исходного запроса возвращает сохранённый
   результат. Отправленные части этой же серии учитываются по подтверждённым
   записям отправки и сами по себе не останавливают хвост.

Проверка охватывает новые сообщения, которые Gate принял до финальной сверки.
Уже начатый запрос к Telegram нельзя отменить этой проверкой. Редактирование
сообщения с тем же ID само по себе не останавливает отправку.

Ответ об остановке возвращается в канал запроса. Для серии, запланированной на
будущее, Work может получить статус через `gate_get_reply_context`. Схема
PostgreSQL совпадает с основной веткой. Используются существующие таблицы
сообщений, входящих квитанций и черновиков.
