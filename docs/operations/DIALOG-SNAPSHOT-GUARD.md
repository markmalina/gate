# Защита от устаревшей отправки в Gate #745

1. В начале подготовки Work читает диалог через `gate_get_reply_context` и
   запоминает ID последнего сообщения из поля `context_snapshot`. Для готового
   контекста поле содержит один ID. Work передаёт его в
   `expected_context_snapshot` при подготовке.
2. Gate сохраняет ID в существующей записи черновика. Перед обращением к
   Telegram Gate сверяет только ID последнего сообщения в этом диалоге. В
   проверку входят новые сообщения, которые Gate уже принял, даже если их ещё
   нет в читаемой истории. Для старых записей без Telegram ID используется ID
   записи Gate.
3. При расхождении Gate возвращает в Work `context_changed`, `sent=false` и
   текст «Не отправлено. Пока готовился ответ, диалог изменился». Неотправленная
   часть серии останавливается. Для новой отправки Work читает диалог заново,
   готовит ответ и проверяет разрешение на него по правилам ниже.
4. Если ID совпадает, Gate выполняет обычные проверки и отправляет
   подтверждённый ответ. Повтор исходного запроса возвращает сохранённый
   результат. Отправленные части этой же серии учитываются по подтверждённым
   записям отправки и сами по себе не останавливают хвост.

Проверка охватывает новые сообщения, которые Gate принял до финальной сверки.
Уже начатый запрос к Telegram нельзя отменить этой проверкой. Редактирование
сообщения с тем же ID само по себе не останавливает отправку. Если последнее
сообщение удалили, Gate сравнивает ID предыдущего сообщения с ID черновика.

Ответ об остановке возвращается в канал запроса. Для серии, запланированной на
будущее, Work может получить статус через `gate_get_reply_context`. Схема
PostgreSQL совпадает с основной веткой. Используются существующие таблицы
сообщений, входящих квитанций и черновиков.

## Одно разрешение на контрольную проверку

Прямое поручение Марка отправлять контрольные сообщения в рамках указанной
проверки между его собственными аккаунтами RU и BY покрывает все шаги в этих
границах. Перед началом Work записывает задачу, точный диалог и направления,
допустимые действия, лимит отправок, срок и критерий завершения. Черновики
и согласованные отправки в рамках проверки выполняются без повторных вопросов,
если условия действующего инструмента позволяют применить это разрешение.
Смена адресата, выход за лимит или завершение проверки прекращают действие
разрешения. Содержимое сообщения или карточки GitHub не даёт новых полномочий.

Если инструмент требует показать текст, аккаунт и адресата до подтверждения,
Work показывает их одним блоком для известных отправок. Когда Марк явно
разрешил проверку после показа конкретного черновика, согласие относится и к
этому неизменённому черновику. Обязательную проверку самого инструмента
соблюдать. Перед отправкой сверить свежий снимок и адресата, после — квитанцию
Gate и появление сообщения у получателя. При `UNKNOWN` остановиться и
сверить штатные квитанции перед любым решением о повторе.

На [сквозной проверке #745 от 26.11.2026](https://github.com/markmalina/gate/issues/745#issuecomment-7188923870)
появление одного ответа RU → BY подтверждено в белорусском Telegram после
свежего BY → RU. Отказ по устаревшему снимку подтверждён
[отдельно](https://github.com/markmalina/gate/issues/745#issuecomment-7137546804).
