# Watch → Gate → Mark

[Gate #770, пункт 4](https://github.com/markmalina/gate/issues/770) ·
[Регламент Work](https://github.com/markmalina/ai/blob/main/WORK-RULES.md).

## Карточка и полный текст

Новая запись в Dropbox создаёт раннюю карточку через действующий серверный
GitHub App. В теле карточки виден прежний `event_id`. Gate использует тот же ID
для записи в архиве и для обновления этой карточки после расшифровки.

После сохранения записи Gate ведёт состояние по версиям. При каждом commit
существующий Watch writer получает сигнал, а после восстановления находит
ожидающую версию в PostgreSQL. Он сверяет репозиторий, автора, номер карточки,
маркер и ревизию источника. При неизвестном ответе на изменение тела
перечитывает его перед возможным повтором. При неизвестном ответе на создание
комментария ждёт точного совпадения сохранённой части при чтении. Отсутствие
комментария в выдаче не разрешает создать копию. Нет повторной расшифровки.

Короткий текст находится в теле карточки. Длинный текст доступен по порядку
в комментариях от того же App. Блок `gate-watch-status:v1` содержит состояние
и версию публикации. В готовом блоке `gate-watch-text:v1` указывает SHA-256,
количество частей и их расположение. В режиме `comments` читайте все
страницы комментариев и выбирайте части с теми же `event_id` и SHA-256.
Собирайте `1…N` по номеру. Пропуск или несовпадение не считается полным
текстом. Когда Марк просит открыть конкретную запись, ChatGPT использует
действующий защищённый Gate M с селектором `watch-voice:<event_id>`.
В защищённой квитанции `mark_publication` показывает требуемую и
подтверждённую версии, время подтверждения и безопасный код ошибки.

Work Mark перечитывает карточку и комментарии по действующему
[AGENTS.md](https://github.com/markmalina/mark/blob/main/AGENTS.md).
Признак нового текста — новый проверенный SHA-256. Если SHA-256 совпал,
новый служебный статус сам по себе не требует повторного показа текста.
Показ в чате, принятие и исполнение — отдельные действия.

## Настройка и приёмка

- `GATE_WATCH_MARK_UPDATES_ENABLED` включает обновление карточек через
  действующий GitHub App.
  Для подтверждённых старых карточек задайте от 1 до 12 уникальных
  `event_id` в защищённом `GATE_WATCH_MARK_BACKFILL_EVENT_IDS`.
  Точный список должен быть согласован на каждый запуск. Сопоставление всех
  записей с существующими карточками проверяется до регистрации версий.
  Очистите список после проверки всех карточек.
- В `watch_voice_actions.delivery_counts` учитываются подтверждения старого
  publisher и актуальные подтверждения App writer. Статус распознавания
  смотрите отдельно в `transcription_counts`.
- После согласованного выпуска проверьте deployed SHA, готовность Gate
  и действующий App writer. Через уже подключённый Gate M запросите одну
  сохранённую запись по `watch-voice:<event_id>` и сверьте её с карточкой.
  Для одной новой короткой записи снимите времена Dropbox, архива Gate,
  первой карточки, сохранения текста и подтверждённого обновления Mark.
  Сверьте один `event_id`, одну карточку и полный текст. Отдельно проверьте
  повтор источника и восстановление после контролируемого сбоя, не повторяя
  внешнее распознавание.
- При расхождении scope, дубликате, регрессии готовности или неизвестном
  внешнем эффекте остановите и сверьте результат. Для остановки публикации
  выключите `GATE_WATCH_MARK_UPDATES_ENABLED`. Если нужен откат, используйте
  предыдущий подтверждённый SHA приложения и оставьте добавочные колонки,
  пока требуется сохранение очереди и доказательств. Не удаляйте карточки,
  комментарии и сохранённые оригиналы для повторной проверки.
