# Инженерный контракт. Gate MTProto RU v4.0

Приложение к [техническому заданию](MTPROTO_RU_SPEC_V4.md). Нормативные требования ниже относятся к будущей разработке. Состояние сегодняшнего сервиса указано в основном документе. Испытания обозначены идентификаторами из [программы приёмки](MTPROTO_RU_ACCEPTANCE_V4.md).

## 2. Подключение аккаунта и жизнь worker

1. Диагностика различает наличие защищённой конфигурации, расшифровку, успешный вход Telegram, совпадение с ожидаемым владельцем и активность worker. Возвращает время, ревизию и причину. Неизвестное состояние представляется явно.
2. Перед новым входом проверить существующую RU-привязку и действительность сессии через ограниченную проверку авторизации. Новое API-приложение требуется лишь при установленной необходимости. Вход идёт на защищённой странице Gate. QR с ограниченным сроком и альтернативный код для входа с одного телефона, при необходимости 2FA. Параметры приложения, код, пароль и содержимое сессии не попадают в Work, журналы, резервные отчёты и GitHub. Отмена или истечение входа удаляет временные данные. [QR-вход Telegram](https://core.telegram.org/api/qr-login)
3. Привязка фиксирует подтверждённого пользователя Telegram, установку Gate, аккаунт RU и поколение сессии. Сессию сохранять зашифрованной вместе с ревизией, версией ключа и нужными данными дата-центра. Ключ хранится отдельно. Изменение основного дата-центра переживает рестарт. Временный клиент передачи медиа не может перезаписать основную сессию.
4. Исполнитель получает исключительное владение до соединения. Реестр охватывает worker, вход, проверку авторизации, старый CLI и чтение контактов: путь присоединён к общему владению или отклоняется до подключения. Две web-реплики или перекрывающиеся релизы не могут открыть два клиента с одной сессией.
5. Режим по умолчанию — исполнение поручений. Для истории и ожидания ответа бота используются ограниченные запросы на время задачи. Уведомления посторонних диалогов не запускают действия. При QR-входе допускается отдельный краткий режим, нужный для такого входа.
6. На подключение, захват/продление владения, запрос к БД, завершение и отключение заданы конечные тайм-ауты. Потеря связи с БД или просроченная проверка снимает готовность и закрывает допуск к новым изменениям. Следующий worker подключается после доказанной остановки старого. Истечение таймера само по себе не доказывает остановку процесса.
7. Пауза блокирует новые действия. Отмена блокирует ещё не начатые шаги. Отзыв полномочия исключает дальнейшее использование, а собственный статус, квитанции и отмена остаются доступны владельцу в его контексте. Завершение активной сессии Telegram требует отдельного точного действия. Возобновление заново проверяет привязку и права.

## 3. Объекты и постоянные данные

Имена таблиц выбираются при интеграции с существующей схемой. Обязательны следующие ключи и правила.

| Объект | Состав и инвариант |
| --- | --- |
| Привязка, сессия, владение | Установка, workspace, RU account, проверенный Telegram user, приложение, поколение, зашифрованная сессия, поколение ключа, ревизия, ID процесса и запуска, SHA сервиса, время heartbeat, признак остановки. Запись по ожидаемой версии. |
| Цель и сообщение | Ключ объекта включает аккаунт, тип и ID peer. Ключ сообщения включает этот peer и message ID. Тема и родитель хранятся отдельно. Уникальные ссылки Gate непрозрачны, с ограниченным сроком, привязаны к владельцу, клиенту и цели. Access hash хранится защищённо. «Избранное» и собственный user ID нормализуются в одну физическую цель. Численные ID разных типов не смешиваются. |
| Полномочие и контекст содержимого | Владелец, проверенный OAuth-клиент, установка, аккаунт, задача, разрешённые операции, цели, лимиты, срок, версия/отзыв. Для передачи содержимого отдельная запись о выбранном чате, участниках и допустимых материалах, цели, сроке и основании. |
| Операция | Постоянный `operation_ref`, ключ намерения внутри клиента, цель, типизированный payload и его digest, версия сообщения/прав, транспорт, полномочие, срок, состояние, время и результат. Личное исходящее не зависит от существования ReplyDraft. |
| Попытка и квитанция | Номер попытки, ID её исполнителя и поколения, отдельные отметки резервирования и возможного внешнего вызова, стабильные random ID там, где они поддержаны, ответ Telegram или причина неизвестного исхода. Факт результата можно дописать после перезапуска без повторного вызова Telegram. |
| Контекст наблюдения | Версия наблюдаемого сообщения, ID темы и ссылки на источники. Для Business эхо и RPC-результат сопоставляются с одним сообщением. Признак удаления исключает дальнейшую выдачу старого текста из кэша. |
| Медиа | Приватная ссылка на версию содержимого, владелец, контекст, реальные размер, MIME и hash, срок и связь с сообщением/операцией. Для альбома сохраняются порядок, отдельные части и полученные ID. |
| Поручение с шагами | Постоянный ID запуска, зафиксированные шаги, их целевые объекты, условия и бюджет. Для каждого шага — своя операция или наблюдение, время, ожидаемый признак, фактический исход, положение для продолжения и общий срок. Сами шаги могут использовать существующий журнал операций. |

Одна транзакция резервирует операцию и бюджет, проверяет соответствие версии/отзыва полномочия и ставит запись в очередь. Уникальные ограничения в БД защищают от гонок. Внешний RPC выполняется после коммита и вне транзакции с блокировками. Очередь и квитанции переживают рестарт. Шифрование, архив и ротация должны позволять разбирать незавершённые попытки.

## 4. Доступ из ChatGPT Work

Для каждого инструмента опубликованы JSON Schema входа и выхода, обязательные OAuth scopes, классы действий, ограничения и стабильные коды ошибок. Клиент не выбирает issuer, аккаунт, внутренний ID адресата, права или имя произвольного Telegram RPC. OAuth, полномочие владельца и права чата проверяются отдельно. Неполные claims, неверный клиент, подмена workspace и устаревшие ссылки приводят к отказу до внешнего запроса. Безопасность не зависит от формулировки подсказки модели. [Спецификация текущего кандидата](https://github.com/markmalina/gate/blob/cc874f16f328bdbe0143f8ff175e1bb941cbbbc6/app/api/personal_command_mcp.py) · [OpenAI, подключение MCP к ChatGPT](https://developers.openai.com/api/docs/guides/custom-mcp-server)

| Инструмент из #761 | Вход существующего контракта | Целевой результат |
| --- | --- | --- |
| `gate_personal_command_readiness` | Пустой объект, scope `gate:personal:jobs:read` | Версия контракта, активность, свежесть, возможности и причины блокировки. |
| `gate_personal_command_prepare` | `grant_ref, peer_ref, request_key, text`, scope `gate:personal:send_text` | Неизменяемая операция, цель и предпросмотр. Одинаковый ключ и намерение возвращают прежнюю операцию. |
| `gate_personal_command_execute` | `operation_ref`, scope `gate:personal:send_text` | Повторная проверка полномочия и постановка существующей операции в очередь. Итог доступен по тому же ID. |
| `gate_personal_command_status` и `gate_personal_command_result` | `operation_ref`, scope `gate:personal:jobs:read` | Состояние, прогресс и доступный владельцу результат. Повторный запрос статуса не вызывает Telegram-изменение. |
| `gate_personal_command_cancel` | `operation_ref`, scope `gate:personal:jobs:cancel` | Подтверждённая отмена ожидающей работы, перечень уже выполненных или требующих сверки шагов. |

Кандидат фиксирует в своей схеме `sent=false` и `runtime_connected=false`. До подключения реального диспетчера версионировать схемы, аннотации MCP и ответы API вместе. Проверить их совпадение с инструментами реальной установки и поведение прежних клиентов. Для новых операций вводить отдельные типизированные схемы либо версионированные варианты. Право отправить текст не разрешает управление участниками, callback или работу с чужой историей.

| Новая группа интерфейсов | Обязательные параметры и ответ |
| --- | --- |
| Поиск цели и диалоги | Строка или ссылка, тип, область поиска, предел, курсор. Ответ содержит допустимые метаданные кандидатов, `peer_ref`, срок и отметку неоднозначности. Для форума выдаётся `topic_ref`. |
| Сообщения и поиск | Цель, окно дат или конкретные ID, фильтр, тема, предел и курсор, контекст доступа к содержимому. Ответ содержит сообщения в установленном порядке, границы, ссылки на объекты, полноту и причину усечения. |
| Отправка и изменение | Тип действия, цель, привязанная версия объекта и данные соответствующего типа. Для пересылки отдельно заданы источник и получатель, для удаления — режим и список ID, для изменения роли — конкретные разрешения. Предпросмотр показывает итоговый эффект. |
| Файлы | Ссылка Work на загрузку или ссылка на выбранное сообщение, назначение и режим отправки. Ответ содержит приватную ссылку владельца, размер/hash, срок или покомпонентные квитанции доставки. |
| Функциональный тест | Ссылка на бота, упорядоченные шаги и ожидания, ограничения, срок и полномочие. Ответ содержит ID запуска и каждого шага, состояния и допустимые свидетельства. Журнал допускает возврат из другой сессии того же авторизованного клиента в рамках политики. |

Для обычного текста приложение проверяет digest и точную цель, затем выполняет prepare и execute в рамках одного выданного полномочия. Клиент сохраняет ключ между повторами. При потере ответа восстанавливает операцию по существующему идентификатору намерения или проверяемой паре «запуск + шаг». Если восстановить привязку нельзя, интерфейс показывает неопределённость перед повторной отправкой. Для намеренно второй команды с тем же текстом формируется отдельный ключ.

Квитанция содержит ID операции, состояние, фактический эффект, транспорт, аккаунт, ссылки на цель и объекты, время UTC и доступное представление в МСК, неопределённость, частичные результаты и право последующего шага. Заявление «отправлено» требует подтверждённого создания сообщения. Статус «прочитано адресатом» требует отдельного свидетельства Telegram. Ответ метода постановки в очередь подтверждает только приём поручения.

## 5. Отправка, повторы, отмена и совместимость с Business

| Ситуация | Обязательное поведение |
| --- | --- |
| Сохранено намерение | Состояние `prepared`, затем `queued`, затем `running`. При повторе с тем же ключом и изменённым получателем, содержимым, полномочием или назначением — конфликт. Отмена очереди атомарно исключает захват. |
| Изменение до внешнего вызова | Повторно проверить владельца, полномочие, лимит, права, версию цели/сообщения и срок. Сохранить точку возможного внешнего эффекта. При подтверждённом отказе до вызова показать `rejected`, `expired` или `cancelled` и причину. |
| Изменение после отправки запроса | Подтверждённый результат становится `succeeded`. Разрыв, тайм-аут или авария с неизвестным исходом дают `unknown`. Повтор команды возвращает сохранённый статус. Для callback, создания чата и других действий без надёжного ключа повтора повторный внешний эффект запрещён до разрешения неопределённости. |
| Возврат Telegram спустя время | Добавление точной квитанции по операции, попытке, поколению сессии и проверяемым ID разрешено после истечения старого владения. Противоречащие квитанции требуют сверки. Совпадение текста и времени недостаточно. |
| Лимит Telegram | `FloodWait` и slow mode сохраняют время следующей допустимой попытки. В пилоте изменения автоматически не повторяются. Позднее повтор после доказанного отсутствия эффекта допускается в том же разрешении с ещё действующим сроком. Сбой чтения допускает ограниченный повтор с прежними целью и окном. |
| Пауза, отзыв или отложенная отправка | Остановить оставшиеся шаги. Начатый эффект завершить квитанцией или перевести в `unknown`. Уже принятая Telegram отправка по расписанию отменяется отдельной операцией на сервере Telegram с собственным результатом. [Расписание Telegram](https://core.telegram.org/api/scheduled-messages) |
| Конкуренция | Защита действует по физическому peer и логическому действию на всех доступных путях отправки RU. После доказанной остановки старого процесса неизвестный исход блокирует повтор затронутого действия/конфликтующие операции цели. Независимые разрешённые цели могут продолжать работу. |

Установить финальную проверку во всех доступных путях RU, включая ручные, Business, фоновые отправители и старые CLI, либо исключить их из этого аккаунта до вызова. Проверять очередь и транзакции на реальном PostgreSQL. Для методов с поддержкой Telegram random ID закрепляется на логическом элементе до внешнего вызова. Автоматическое переподключение клиента не должно неожиданно воспроизводить незавершённый запрос изменения.

Эхо Business, ответ RPC и наблюдение в выбранной истории объединяются по точным идентификаторам. Ответ по задаче закрывает только причинно связанные задачи. Самостоятельное сообщение не закрывает все ожидающие ответы в диалоге. Новое входящее, полученное до окончательного допуска, отклоняет устаревший ответ. Work предлагает заново получить контекст. Граница гарантии — уже наблюдаемые Gate события. Смена маршрута, Business connection или формы команды не даёт повторить тот же отклонённый ответ как новое самостоятельное действие. [Живая приёмка существующей защиты](https://github.com/markmalina/gate/issues/745#issuecomment-7188923870)

## 6. Адресаты, сообщения и медиа

- Различать пользователя, бота, обычную группу, супергруппу, канал, связанный чат обсуждения и тему. Отображаемое имя или текущий username не служит постоянным идентификатором. Ссылки раскрываются в ожидаемый тип. Миграция обычной группы в супергруппу требует проверяемой связи старого и нового объектов. При неоднозначности вернуть варианты без чтения лишних фрагментов переписки.
- Для группы фиксировать участника и отправителя, тему и при ответе родительское сообщение. Права участника и состояние темы перепроверяются при выполнении. В канале проверить право публикации и возможность выступить именно с указанной идентичностью. Ссылку на пост закрытого чата показывать только в разрешённом контексте. [Форумные темы](https://core.telegram.org/api/forum) · [ветки сообщений](https://core.telegram.org/api/threads) · [права Telegram](https://core.telegram.org/api/rights)
- Для истории фиксировать верхнюю границу на первой странице, порядок выдачи, окно с часовым поясом и подписанный курсор, привязанный к аккаунту, клиенту, чату, теме, цели обработки и бюджету. Для периода по датам используется полуоткрытое окно от начала первого дня до начала дня после последнего в МСК. Учитывать изменения, удаления, недоступную раннюю историю и истечение курсора. Выдавать `complete`, `partial_reason`, `next_cursor`. Возврат кэша сопровождается проверкой свежести. Поиск и отметка прочтения — разные команды.
- Форматирование преобразуется в поддерживаемые Telegram entities с правильными смещениями UTF-16. Разбиение учитывает границы символов, entities и лимиты типа сообщения. Квитанции частей и родитель цитаты сохраняются. Доступ к исходному и целевому диалогам для пересылки проверяется отдельно, включая защиту контента Telegram. [Форматирование Telegram](https://core.telegram.org/api/entities)
- Входящий файл из Work читается через проверенный механизм текущего клиента. Считать размер, hash и тип по фактическим байтам, ограничивать загрузку до чтения всего файла, проверять адрес и перенаправления у временной ссылки. Частичная загрузка отделена от окончательной публикации. Истёкшая ссылка Telegram при необходимости обновляется только по разрешённому исходному сообщению. Путь к файлу на сервере не является результатом скачивания в Work. [Передача файлов Telegram](https://core.telegram.org/api/files)
- Документ сравнивается побайтно, а сжатое фото — по типу, содержанию контрольного изображения и параметрам после обработки Telegram. Для голоса проверяются тип voice, воспроизведение и длительность. Для видео и аудио проверяются атрибуты и доступность. Для альбома сверить порядок, подписи, число элементов и известные ID. При неполном ответе не приписывать недостающие ID по догадке.
- Данные Telegram, включая названия тем, кнопки и файлы, являются входными данными. Они не меняют цель, полномочия, бюджет, настройки, получателя или разрешение на дальнейшие действия. Для показа в ИИ действуют отдельные правила выбранного чата и материалов. При отзыве прекратить выдачу и очистить соответствующий кэш по политике. [Условия API](https://core.telegram.org/api/terms) · [условия использования контента](https://telegram.org/tos/content-licensing)

## 7. Исполнитель сценария бота

Использовать диалог пользователя с выбранным ботом. Токен этого бота для теста через личный Telegram не требуется. Контракт допускает контроль на собственных синтетических данных и показ «условие выполнено» без раскрытия всего ответа в Work.

| Шаг сценария | Вход и исполнение | Основание для результата |
| --- | --- | --- |
| Запустить или послать команду | Проверить, что цель — бот. Обычный `/start` отправить как сообщение. Поддержать явный start-параметр проверенной ссылки на выбранного бота. Два способа запуска не применяются вместе. | ID собственного сообщения или подтверждённый эффект запуска. Сохранить позицию наблюдения до действия. [Deep links Telegram](https://core.telegram.org/api/links) |
| Ждать и проверить | Определить целевой диалог, ожидаемого автора, окно, границу ID до шага, отслеживаемые сообщения и их версии. Проверки поддерживают текст/его часть, набор надписей кнопок, тип вложения, появление сообщения или его изменение. | Новое сообщение бота, новая версия конкретного сообщения или тип ожидаемого callback-ответа. Старое совпадение, посторонний автор/диалог или событие вне окна не засчитываются. При одновременном ручном взаимодействии и спорной связи вернуть «результат неоднозначен». |
| Нажать текстовую кнопку | Убедиться, что это обычная текстовая кнопка reply-клавиатуры. Сохранить точный ожидаемый текст и цель. Особые кнопки, запрашивающие данные или выбор чата, имеют иной тип. | Собственное исходящее с текстом обычной кнопки и ожидаемый следующий ответ, если он задан. |
| Нажать inline callback | Зафиксировать кнопку в конкретном сообщении: ссылка на сообщение, версия/отпечаток клавиатуры, позиция, видимая подпись и внутреннее соответствие данным Telegram. Повторно проверить перед вызовом. Одинаковые подписи требуют уникального выбора. Произвольные байты callback от модели не принимаются. | Ответ на callback может быть всплывающим сообщением, изменением меню или отдельным новым сообщением. Сформулированное пользователем ожидание определяет успешность шага. Полученный ACK сам по себе не доказывает открытие меню. [Кнопки Telegram](https://core.telegram.org/api/bots/buttons) · [callback пользователя](https://core.telegram.org/method/messages.getBotCallbackAnswer) |
| Закончить, остановить или продолжить | Зафиксировать результат каждого шага. При отрицательном условии, истечении лимита, отказе или неопределённом изменении остановить последующие зависимые шаги. После разрыва читать тот же запуск. | Статусы: прошло, условие не выполнено, тайм-аут наблюдения, отменено, действие недоступно, исход изменения неизвестен. Марк видит число завершённых шагов, первый сбой, допустимое доказательство и остаток. |

Каждый запуск фиксирует список допустимых типов действий, цель, окно, число изменений и предикаты. На старте фиксируется допустимый контекст данных. Тест на чужом боте выполняется только в разрешённых владельцем пределах и в доступном для проверки контексте. Переход к другому боту, URL, Mini App, телефону, платёжному экрану или привилегированному действию выходит за пределы обычного callback. Возврат после тайм-аута наблюдения не отправляет `/start` и не нажимает прежнюю кнопку повторно. Если пользователь ожидает именно меню, всплывающий ответ без меню остаётся отдельным свидетельством.

## 8. Нефункциональные требования и выпуск

Ниже проектные значения пилота, предлагаемые на согласование. Они задают предсказуемые пределы продукта. Telegram и конкретный хост могут вернуть более строгий предел, который Gate показывает до эффекта, когда он известен.

| Параметр | Цель и способ проверки |
| --- | --- |
| Граница пилота | Одна активная RU-сессия. Одна начатая операция изменения на физическую цель. Для первого теста отправки — одно сообщение. Для стандартного теста бота — до 8 шагов, до 3 внешних изменений, по умолчанию до 30 с на ожидание и 120 с на весь запуск. Короткое продление опроса не продлевает полномочие. Для другого объёма у владельца видны новые границы. |
| Выдача и файлы | До 100 сообщений на запрос страницы к провайдеру и до 50 сообщений или 64 КиБ текста на ответ Work, с продолжением. Документ пилота до 8 МиБ. Бюджет целого запроса/пакета ограничен отдельно. Размер и доступные режимы опубликованы в каталоге. |
| Отзыв и доступность | Проверять срок/отзыв до подготовки, постановки и непосредственно перед внешним изменением. Предлагаемые значения для проверки: heartbeat каждые 10 с, устаревание статуса за 30 с, ожидание штатной остановки до 30 с. При недоказанной остановке Gate показывает блокировку владельца сессии. |
| Время ответа | Цель для внутренних запросов статуса и постановки в очередь — P95 до 2 с на тестовой среде, минимум 30 измерений каждого вида. Задержки Work, очереди, Telegram и бота измерять раздельно. Живой пилот фиксирует фактические значения без обещания времени Telegram. |
| Хранение | Временные переданные байты и содержательный кэш — по необходимости, максимум 24 ч в пилоте, с более ранним удалением при отзыве. Обезличенная история завершённых операций — 90 дней как проектное значение. Для незавершённых и неопределённых попыток сохранять минимальное доказательство до сверки. По истечении ключа идемпотентности старый запуск не превращается в новую отправку. |
| Наблюдаемость и стоимость | Счётчики операций по состояниям и коду причины, повторы и предотвращённые дубли, задержки по этапам, глубина и возраст очереди, время последней проверки, время остановки worker. Отчёт показывает окно, знаменатель, ошибки и незавершённые. Учесть минуты CI, процесс worker, БД и хранение. Денежные оценки отделены от подтверждённого счёта. |
| Хранение доказательств | В приватном контексте владельцу доступны положенные ссылки и ID. В Git и общих логах — SHA, версия схемы, вид проверки, агрегаты и обезличенные ссылки на квитанции. Содержимое личных групп, секреты, временные URL, payload кнопок и файлы туда не копируются. |

Имя из адресной книги показывается с источником, совпадения только по имени требуют выбора. Изменение контакта Telegram не меняет Google Контакты.
