# Личный Telegram из ChatGPT Work через Gate. Техническое задание v4.0

**Статус:** на согласовании у Марка Малиновского. **Редакция:** 26 ноября 2026 года. **Продуктовая задача:** [Gate #696](https://github.com/markmalina/gate/issues/696). **Среда пользователя:** ChatGPT Work с подключённым Gate M, включая Android. Аккаунт первой и полной поставки v4 — личный Telegram RU Марка.

Владелец даёт команду на русском, выбирает цель при неоднозначности и получает подтверждение того, что произошло в Telegram. Gate действует с фактическими правами выбранного аккаунта, сохраняет результат через перезапуск и умеет остановить оставшиеся шаги. Первые два прикладных результата — работа в группе, где Марк уже состоит, и функциональный тест бота из пользовательского диалога.

Состав одного ТЗ: этот документ задаёт объём, пользовательские сценарии и спринты. [Инженерный контракт](MTPROTO_RU_ENGINEERING_V4.md) задаёт архитектуру, интерфейсы, данные и требования к эксплуатации. [Программа приёмки](MTPROTO_RU_ACCEPTANCE_V4.md) задаёт условия запуска проверок и ожидаемый результат каждого теста. Согласование относится ко всем трём документам одной ревизии.

Названия, тексты и кнопки выше — вымышленные примеры. Рабочая цель берётся из поручения. Для группы статус членства и права проверяются от RU-аккаунта, установка Gate-бота в эту группу не требуется. Цель теста — указанный Марком доступный бот. Для первой живой приёмки используется контролируемый тестовый бот с известными ответами и без платных действий.

### Какие действия требуют особой среды

Права проверяются перед каждым изменением. Например, участник может отправлять в доступную тему, а закрепление, приглашение, редактирование канала и управление ролями зависят от прав в конкретном чате. Когда Telegram предлагает анонимного отправителя или отправку от канала, команда «от меня» требует подтверждённой личности RU. При несовместимых правах результат содержит причину и выполненные шаги.

Охват v4 — личные облачные диалоги, группы, супергруппы, форумы, каналы, комментарии в связанной группе, «Избранное» и пользовательские диалоги с ботами. Для комментария Gate проверяет связанный чат и ветку. Для недоступной личной группы нужны действительное членство или явно поручённое вступление. Прежний выбор аккаунта RU распространяется на этот проект. BY остаётся вне объёма подключения и живых проверок MTProto.

## 4. Два пилота и одно разрешение на поручение

**Группа.** Gate разрешает точную ссылку или помогает выбрать единственное совпадение, проверяет членство, возможность писать от себя и тему. Для ответа связывает поручение с ID и наблюдаемой версией сообщения. При успехе показывает группу, тему, ID созданного сообщения, ID родителя для ответа и открываемую ссылку, когда Telegram её предоставляет. Вышедшему участнику, чату только для чтения, закрытой теме или устаревшему контексту соответствует конкретный результат.

**Бот.** Владелец задаёт бота, шаги и ожидаемые признаки, например появление двух кнопок после «Каталог». До старта Gate проверяет тип аккаунта, ограничение времени и разрешённые изменения. После каждого действия наблюдает выбранный диалог и фиксирует совпадение, несовпадение, тайм-аут или неопределённый исход. Для кнопки используются конкретные сообщение и версия клавиатуры. Бот может изменить прежний текст, прислать новое сообщение либо вернуть только всплывающий ответ. Приёмка указывает, какой из этих вариантов ожидается.

**Полномочие.** Один понятный допуск охватывает действия конкретного поручения. В его карточке указаны аккаунт, цель, разрешённые команды или кнопки, окно наблюдения, предельное число изменений и срок. Сервер проверяет их на каждом шаге. Пока условия соблюдены, Gate не запрашивает у Марка повторное разрешение на тот же шаг. Изменение адресата, выход за лимит или новый необратимый эффект требует отдельного решения только для изменившейся части. Настройки подтверждений самого Work учитываются при испытании.

**Данные групп.** Доступ члена группы к Telegram и передача чужого содержания в ИИ имеют разные основания. Для выдачи текста, медиа, подписей и содержательных фрагментов в Work Gate проверяет допустимый контекст, участников, цель, срок и отзыв согласия. При отсутствии основания доступны разрешённые действия с указанной целью и квитанции в предусмотренном объёме. Для пилотов используются собственные контрольные тексты и согласованный тестовый контекст. [Условия Telegram API, §1.5](https://core.telegram.org/api/terms) · [правила использования контента](https://telegram.org/tos/content-licensing)

## 5. План разработки и приёмки

Разработка начинается со спринта S1 после согласования v4.0. Каждый последующий спринт получает отдельный наблюдаемый результат в #696. Сроки подключения, ожидание Telegram и стоимость новой инфраструктуры измеряются отдельно от времени разработки. Если отдельный тест файла или чтение чужого контента требуют внешнего решения, независимые поставки текста и бота могут продолжаться в разрешённом контексте.

## 6. Ответственность и решение владельца

Gate отвечает за код транспорта, хранилище полномочий и операций, клиент Work, подготовку проверок и сбор доказательств. Под «клиентом Work» здесь понимается интеграция Gate M и её контракт. Исполнитель инфраструктуры отвечает за установку, ключи, резервное восстановление и остановку конкретного процесса через зарегистрированный маршрут Gate. Марк утверждает объём, получает защищённый вход при фактической необходимости и принимает пользовательские результаты.

**Решение сейчас:** согласовать v4.0 и открыть S1. Реализация, слияние кода и живые действия имеют отдельные записи о фактическом выполнении. Критерии готовности спринтов приведены выше. Протокол финального решения и шаблон доказательств — в [программе приёмки](MTPROTO_RU_ACCEPTANCE_V4.md).
