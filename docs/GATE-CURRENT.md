## Контракты рабочих маршрутов

### Watch

Запись проходит Galaxy Watch → телефон/Dropsync → Dropbox `/Alpha/Voice` → защищённый архив Gate → транскрипция → закрытая карточка Mark. Событие загрузки в Dropbox отдельно от записи на часах. Один ID связывает оригинал, статус и текст, а ссылки на оригинал ведут через защищённый Gate. [Маршрут ранней карточки](operations/WATCH-EARLY-CARDS-RELEASE.md) · [публикация в Mark](operations/WATCH-MARK-PUBLICATION.md).

Повтор доставки, рестарт и потеря подтверждения разбираются по идентичности источника и сохранённым квитанциям. Не переводить запущенную операцию с неизвестным исходом обратно в очередь без сверки. Живой образец `n=1` показывает работоспособность маршрута. Для оценки P95 и устойчивости нужен согласованный период наблюдения и достаточная выборка.

### Calls

Webhook фиксирует ожидающее событие, цикл приёма читает Dropbox delta и сохраняет ревизию. Длительная обработка идёт в отдельном цикле. Текст и сводка доступны через защищённый архив Gate M. Решение о создании карточки Mark для каждого звонка остаётся отдельным. Общий `webhook_received_at` нельзя приписывать конкретному файлу. [Вход Calls](dropbox-call-intake.md) · [цикл воркера](../app/worker/dropbox_calls.py).

В #788 остаётся длинный оригинал, отклонённый по длительности. В исходниках предел Calls 60 минут и максимум 20 частей по 180 секунд. Согласовывать оба ограничения, полноту текста и поведение при неопределённом исходе. Сначала метаданные уже сохранённого оригинала и длинная синтетическая проверка. Массовый перезапуск архива требует отдельного решения.

### Транскрипция и чтение из Work

Серверный режим определяется [политикой Gate](policies/GATE_TRANSCRIPTION_MODEL_ACCESS_POLICY.md) и [точным model-access lock](../model-access.lock). Активная обычная модель в срезе — `gpt-4o-mini-transcribe`, идёт подготовка замены по [#859](https://github.com/markmalina/gate/issues/859#issuecomment-7141608789). Показатель бюджета Gate относится к внутренней резервации; остаток и доступность провайдера проверяются отдельно.

Gate M предоставляет защищённое чтение оригинала и сохранённого текста. Для распознавания самим Work отдельно доказываются наличие speech-инструмента, совместимая запись результата и отсутствие второго оплаченного вызова на ту же запись. Доступ к файлу сам по себе подтверждает только чтение.

### Актуальность ответа

Work читает последний ID сообщения при подготовке. Если перед допуском к отправке Gate обнаруживает смену контекста, операция возвращает `context_changed` и `sent=false`. [Контрольный сценарий #745](https://github.com/markmalina/gate/issues/745#issuecomment-7138499533).

Гарантия относится к событиям, уже сохранённым Gate к моменту допуска. Уже начатый внешний HTTP-запрос назад не отзывается. Для живой приёмки остаётся свежий контрольный ответ после нового входящего. Защита отправки, решение модели и отправка пользовательских сообщений требуют собственных критериев и допуска. [Исходный контракт](operations/DIALOG-SNAPSHOT-GUARD.md).

## Выпуск и продолжение работы

1. Прочитать [AGENTS.md](../AGENTS.md), [WORK-PARENT.json](../WORK-PARENT.json), [bootstrap](work-bootstrap.md) и рабочие правила.
2. В [#787](https://github.com/markmalina/gate/issues/787) найти конкретное issue, последнюю квитанцию и lease. Проверить актуальные commit, CI, production и незавершённые операции. Не начинать дублирующий этап при активном lease.
3. Зафиксировать один результат, базу, проверку, ограничения, исполнителя и отдельные состояния source, CI, merge, release и product acceptance.
4. Для разрешённого рабочего выпуска пользоваться зарегистрированным [#751](https://github.com/markmalina/gate/issues/751) на точном зелёном main, сверять полный отпечаток у провайдера и состояние сервиса. Разрешения и критерии восстановления приведены в AGENTS. Документация сама по себе не расширяет scope.
5. Данные и секреты оставлять в соответствующем защищённом контуре. В GitHub сохранять только дозволенные агрегаты, безопасные квитанции и ссылки. Неподтверждённый внешний исход не повторять вслепую.
